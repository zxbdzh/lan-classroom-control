## 已复现的身份问题

- 原教师身份判断使用 MAC 原始文本比较。同一地址的冒号、连字符、大小写或紧凑格式不同，可能无法匹配原记录；持久学生 ID 改变时会新增记录。
- 原实现把“同一持久学生 ID、MAC 不同”一律当作克隆机，即使原记录已经离线。启动时网卡选择变化或更换网卡会派生新 ID，旧记录继续保留。
- 注册、旧连接断开及心跳处理没有共享注册锁；旧连接迟到的心跳可能把已离线的新会话重新标记为在线。

这些路径由失败回归测试复现后修正，但没有把它们直接认定为截图所示现场的唯一根因。

## 修正原则

1. 继续使用学生端已持久化的设备 ID，不用主机名或当前 IP 当作唯一身份。MAC 统一规范化，拒绝空地址、全零、广播及无效地址匹配。
2. Windows 学生注册增加 SMBIOS UUID 的 SHA-256 摘要作为辅助硬件提示，不发送原始 UUID，不作为认证凭据。读取失败或固件 UUID 全零、全一时退回原持久 ID/MAC 路径。
3. 持久 ID 和已知硬件提示一致时，即使 MAC 改变、旧连接还未超时，也复用原记录及分组。硬件提示不同的克隆机保留独立身份，原机离线时同样不能被吞并。不单凭共享固件 UUID 合并不同安装身份。
4. 旧客户端没有硬件提示时，同 ID 的离线记录允许重连；同 ID、不同 MAC 的在线冲突仍分开。旧客户端在“原机离线、克隆复制 ID、双方硬件提示都缺失”时仍有歧义，应一起升级双端；不能保证凭现有字段区分全部克隆或还原环境。
5. 注册解析与连接替换串行，旧连接断开及心跳不能覆盖当前连接的在线状态。旧客户端缺少新字段时保留已记录的硬件提示。

## 已有重复记录的保守处理

只归档 MAC 规范化后相同、主机名相同、硬件提示不冲突、分组不冲突且没有永久策略的离线副本。归档记录保留在数据库中并映射到保留记录，不删除原始操作历史；全班、分组及显式作用域不会再次向副本重复下发。别名持久化后，教师重开也不重新显示；旧连接迟到事件不能复活副本。

保留记录的设备 ID 不变，因此原来绑定该 ID 的分组、座位位置和应用策略不会被改写。存在分组或永久策略冲突、不同硬件、只有同名但 MAC 不同的旧记录不会自动吞并，需要现场证据或后续显式整理。此次没有直接打开、删除或批量修改用户正在使用的教师数据库。
