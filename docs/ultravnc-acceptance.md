# UltraVNC 接入与验收记录

记录日期：2026-11-15。代码、单元测试、冻结构建与目标系统实际验收分开记账。

## 教师安装与主窗口补测

已在三台 headless 来宾组成的独立 NAT Network 完成教师安装及七页主窗口主要按钮链路，实际按钮驱动两台学生，不使用实验 API 代替。Win10 教师首次安装、覆盖升级及启动通过；同一最终教师包另在 Win7 安装/升级、启动、指定 Win10 黑屏与恢复，并在两种系统实测座位拖动及重开持久化。Win7 教师没有重复全部七页流程。

本阶段修复六处实际问题：电源按钮异常、桌面代理缺少防火墙放行、切设备残留旧进程表、会话 0 无法注销桌面、深色弹窗对比不足、点击座位销毁拖动源。两台分别从教师按钮实际注销、重启、关机并重新连接，文件与目录落盘哈希、禁软件完整路径规则、禁网前后出口探测、双机黑屏、独立 Viewer 与恢复链路均有证据。最终完整自动化回归 **357 passed**。

**仍有失败与未测范围**：Win10 一次广播持续黑帧，停止重开后恢复，尚未确认根因；Win10 历史 0x133 蓝屏和本阶段启动停滞也未根治。有效签名更新与硬件唤醒未测，只有无效包错误链路和唤醒包发送；真实 WiFi、原失败终端、完整卸载矩阵等也未通过现场验收。applied 只说明指令应用，不能替代可见画面验证。详细按钮矩阵、失败证据与收尾结果见 [教师端实际验收](virtualbox-lab.md#教师端安装与主窗口实际验收)。

当前教师包为 `.artifacts/candidate-teacher-ui-seats-20261115/installer/LanClassroom-Teacher-Setup.exe`，学生包为 `.artifacts/candidate-teacher-ui-final-20261115/installer/LanClassroom-Student-Setup.exe`；已用于来宾安装，未发布。包哈希及回归记录见上述验收文档。

## 已落地的行为

- 保留教师端，学生端启动项目专用的 `LanClassroomVNC` 按需服务。独立 Viewer 从学生端应用完成回执读取端口，默认 TCP 15900；不再传输旧远控 JPEG 或旧远控输入。
- Win10 原版服务在没有 Viewer 连接时，单独停止仍实测需 9.526 秒。现在先正常停止 0.6 秒，再只结束已核实服务配置、进程路径和父子关系的项目 VNC 进程；保留 PID 复用保护，确认进程退出与服务停止后才恢复遮罩并回报成功。已有 STOP_PENDING 不重复发停止。两台原版 Viewer 的八次有效关闭实测约 0.80–1.75 秒，详见下方记录。
- 巡视默认使用有界单槽、可重连的 TCP 通道，同一帧不再同时发 UDP 和 TCP。
- 黑屏与远控互斥显示，黑屏的课堂意图仍保留。教师在远控中解除黑屏后，退出远控不会再次黑屏；“全部恢复”也清除临时状态。
- 输入锁检查后端返回值，Windows 的锁定与解锁由同一线程执行。备用钩子不再因回调返回 False 而立即退出。Windows 锁定线程有独立超时。
- 学生服务与桌面代理都有失联恢复路径，另有 SYSTEM 子进程监视服务实例与恢复期限。恢复失败会保留状态并重试。旧守护以所有者标识与互斥锁避免干扰重启后的新服务。
- 文件准备移到后台，每次落盘由接收端哈希确认；失败设备可单独重试，连续部分文件可续传。断线保留 `.part`，哈希不匹配会丢弃坏部分文件重新接收。文件夹解压完成后才公开目录，同名目录另存副本。
- 禁软件按名字和可选完整路径匹配，PID 复用保护保留；省略 `.exe`、带引号路径可以匹配。关闭失败会回报，永久策略继续重试。
- 禁网使用 Win7 可用的防火墙 COM 接口，设置并读回规则。只阻断教师及配置白名单的补集，覆盖 IPv4/IPv6 和所有协议，不以“全阻断加允许规则”制造冲突。防火墙未启用、无权限、域策略不允许等情况返回失败。
- 克隆镜像复制设备 ID、但 MAC 不同的设备，在教师端分配不同标识，避免互相替换连接。克隆虚拟机仍须使用不同的 MAC。
- 修复服务启动桌面代理时 `DuplicateTokenEx` 的参数次序，改用具名参数。已在本机只复制当前进程令牌验证 API；不把此结果当成目标系统服务启动已通过。
- 教师/学生安装器按程序添加入站放行规则，覆盖公共、专用和域网络，学生桌面代理有独立规则，卸载时移除。添加失败会中止并显示错误。安装包排除 Viewer 自动保存的 `.vnc` 会话设置，构建只收集固定上游文件；UltraVNC 同版本同内容文件不强制覆盖，真正更新且占用时允许系统重启替换。教师安装与覆盖升级已经来宾实测，完整卸载矩阵仍未验收。

### 禁网期间继续远控与分发

同一教师对两台同时禁网后，原可用的公网 TCP、HTTP 和两种 UDP DNS 被阻断，教师 TCP 19532 保留。原版 Viewer 继续显示画面并接受键鼠，关闭后两台均能在禁网状态重新连接；项目同批分发的空文件、中文文件、嵌套 8 MiB 文件，在两台独立算出的 6 项 SHA-256 全部一致。8 MiB 夹具高度可压缩，传输量约 33 KiB，本轮不能用于吞吐评估。

只解除 Win7 后，其相同出口探测恢复，Win10 仍被阻断。全部恢复后两台规则清零、VNC 服务与进程退出、学生服务运行。新增四次关闭 Viewer 到真实 applied 的计时为 Win7 **0.828 / 0.860 秒**、Win10 **0.860 / 0.906 秒**。

Win7 首次全部恢复后的公网 UDP DNS 有一次超时，其他出口正常且规则为 0；没有更改策略，重复相同探测返回 65 字节。原失败报告与重测报告都保留，未确认原因。部分 Win10 初始截图为黑帧或旧画面，后续可见画面和输入变化已核对；不凭窗口标题断言连接可用，也不据截图时序宣称输入延迟达标。

本轮仅增加实验脚本与证据，没有修改产品代码或重建候选包。独立断言输出 `COMBO_EVIDENCE_PASSED guests=2 network_reports=8 file_hashes=6 viewer_exits=4`，汇总为 `.artifacts/virtualbox-lab/20261115/combo-validation.json`，另纳入一次 DNS 异常。详细证据见 [VirtualBox 组合验收](virtualbox-lab.md)。

当时尚未测的教师端来宾安装、主窗口主要按钮、两台学生注销/重启/关机及自建程序完整路径禁用，现已补测，见文首；有效签名更新与硬件唤醒成功链路仍未测。完整安装升级卸载矩阵、真实 WiFi、原故障终端、多屏、100 次目标系统切换、输入延迟、已建立外部连接/HTTPS/QUIC/真实 IPv6 出口、强杀服务及文件断线/磁盘失败仍未实测。Win7 PowerShell 2.0 长脚本的 MCP 同步调用仍有超时；通过报告落盘、取回与内容断言确认结果，没有将这些调用记成正常同步执行。

## 后台虚拟机怎么开

**当前选用 VirtualBox + MCP，已由 Magpie 管理并分发给 Codex。** VirtualBox 核心已由用户安装，用户提供的 Win7 ESD 已部署到桌面，后台管理及真实禁网基础验收已完成。进展与证据见 [VirtualBox 后台验收环境](virtualbox-lab.md)。以下 Hyper-V 脚本保留为旧方案记录，不作为当前验收入口。

本机约 64 GiB 内存；Hypervisor 已存在，但调查时 Hyper-V `vmms` 停止，当前终端没有管理可选功能所需的提升权限。常见位置未发现现成 Win7/Win10 虚拟磁盘；没有进行整盘搜索，没有下载来历不明的系统镜像。

提供 `scripts/Start-ClassroomLab.ps1`，在有权限的终端中使用合法、已安装系统的 BIOS/MBR VHD/VHDX：

```powershell
.\scripts\Start-ClassroomLab.ps1 `
  -TeacherVhd F:\Images\Teacher-Win10-BIOS.vhdx `
  -Win7Vhd F:\Images\Win7-SP1-x64-BIOS.vhdx `
  -Win10Vhd F:\Images\Win10-x64-BIOS.vhdx `
  -Start
```

以上是调用示例，镜像路径不是已存在资源。脚本创建三台第 1 代虚拟机与差分磁盘，父盘不修改；总计启动内存约 10 GiB，每台 2 vCPU。只使用专用 Private 交换机，不创建外部交换机、不改宿主 WiFi、不打开 VMConnect、不自动安装 Hyper-V 或重启宿主机。脚本尚未在本机实际创建虚拟机。

建议三台来宾固定为同一测试子网的不同地址，教师 `.10`、Win7 `.21`、Win10 `.22`。先做隔离网络中的发现、远控、黑屏和分发；外网禁用测试还需可控的联网出口或独立路由虚拟机，Private 网络本来不能上网，不能据此认定禁网通过。

Win7 需先具备 SP1、SHA-2 与 UCRT 更新。使用普通学生账户登录，安装包由管理员安装。安装器不要安装到宿主；正式包的 `--diagnostics <绝对输出文件>` 可先验证依赖加载，无需打开界面或启动服务。

## 来宾中的验收顺序

1. **冻结安装包**：Win7/Win10 各执行安装、重启、普通用户自动启动、覆盖升级、卸载；先跑只读启动诊断，记录系统版本、DPI、网卡与 UltraVNC 版本。
2. **UltraVNC 对照**：先用原版 Viewer 连接同一来宾，再从教师端启动；同样的分辨率与图像配置下对比首屏、文字输入、拖动窗口、管理员窗口和 UAC，避免将上游限制误记成集成问题。
3. **至少两台学生同时黑屏**：只远控其中一台；另一台必须继续黑屏。远控内分别执行“解除黑屏”和保留黑屏退出，核对最终状态。连续切换 100 次，覆盖双屏、125%/150% DPI、插拔显示器。
4. **异常恢复**：分别关闭 Viewer、断教师网络、强杀学生服务、卡住/结束代理，再恢复。记录真实解锁、遮罩移除、网络恢复、VNC 端口关闭用时，确认服务重启后旧守护不清除新状态。
5. **发文件与禁软件**：空文件、大文件、中文名、嵌套目录、同名目录、磁盘写入失败和断线重试。逐台比对 SHA-256；禁用普通和提权应用、重复启动、重启持久化、解除后重新启动。启动后短暂出现再关闭符合当前软件禁用实现。
6. **禁网**：先证明出口可用，再禁用；测试已有连接和新建连接、IPv4/IPv6、TCP/UDP、DNS/HTTP/HTTPS/QUIC，以及局域网代理。教师心跳、文件、VNC 必须同时保持；解除和服务异常退出后再证明出口恢复。防火墙关闭/域策略拒绝应显示失败，不得显示成功。
7. **网络条件**：通过独立测试路由器模拟 5/10/20 Mbps、50/100 ms 延迟、1%/3% 丢包和 3 秒断线，覆盖远控与分发同时运行；随后实际 WiFi 和原失败终端试点。虚拟交换机和本机回环不能替代无线干扰、多站竞争和 AP 隔离测试。

拟定目标：首屏不超过 5 秒、普通桌面输入 P95 不超过 300 ms、黑屏/解除不超过 2 秒、失联恢复不超过 15 秒。本轮仅对上述有限 Viewer 关闭样本取得低于 2 秒的成绩；首屏、输入 P95、目标系统 100 次切换和精确失联恢复时间仍未形成验收结论。黑屏也不宣称能够封锁 Ctrl+Alt+Del 等 Windows 安全界面。
