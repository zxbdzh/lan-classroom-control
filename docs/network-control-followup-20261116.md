## 已复现及修正

1. Windows 端重复禁网只检查内存 `_blocked`。规则被外部清理后，内存仍为 true，再次点击会直接返回成功，不重建规则。现每次 Windows 禁网均检查系统策略并重建本项目规则。单测及真实来宾均验证了这一恢复路径。
2. 白名单允许填 `0.0.0.0/0` 或 `::/0`，会放行整个地址族，仍回报成功。现拒绝这两种配置以及多个网段合并覆盖整个地址族的情况。无效 IP、URL 不再被默默忽略，而是返回明确失败原因；不提供按 URL 封禁功能。
3. 教师状态栏只显示“外网限制已下发”，不跟随学生执行结果。现等待真实回执，显示策略已应用数量以及第一台失败设备和原始原因；最近操作的提示信息保留各设备详情。策略已应用仍不代表已经通过外网连通性实测。

关闭防火墙、无管理员/系统服务权限、域策略不允许本地规则仍返回失败，不擅自启用全机防火墙或修改域策略。新回执显示用于识别这些实际环境差异，不将其掩盖为成功。

## 证据和失败保留

本地临时根目录：`F:\tmp\classroom-virtualbox\20261116\network-policy`，不提交探针、二进制、原始日志或截图。

- `win10-v2-report.json`、`win7-v4-report.json`：最终有效阶段报告。
- `regression.xml`：本轮完整离屏回归结果，实际成绩以该文件为准。
- Win7 首次登录失败及未提权报告保留，不计通过；复用已授权实验凭据登录，使用来宾的 RunAs 后取得实际管理员报告。
- 第一版临时探针的 HTTP 模块被同名函数遮蔽，不能据此判断 HTTP/HTTPS 通过；修正命名并强制要求两个协议的 200 基线后重新执行，最终两份报告不受影响。
- 临时探针起初没有采用正式构建的 UCRT 排除规则，Win7 提示缺 API-set DLL；沿用仓库 `exclude_host_ucrt` 后重新构建才可运行。正式产品构建已有该规则，此失败不表示发布安装包有同一问题。

后续现场定位应取得教师和学生实际版本、所选作用域、禁网后失败回执、学生服务状态与对应时段日志；若规则已应用仍能上网，再核对目标地址是否为白名单中的代理/网关及连接是否为缓存或旧连接。不能仅凭此次实验通过宣称用户问题根治。
